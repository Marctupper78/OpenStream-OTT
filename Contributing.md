# Contributing to OpenStream OTT

Contributions of all kinds are welcome. Whether you're fixing bugs, improving the user interface, enhancing streaming functionality, optimizing performance, adding new features, or improving the documentation, every contribution helps make this project better.

If you find this project useful, consider sharing it with others, referencing it in your projects, or giving the repository a ⭐ to support its development.

Please remember to follow our **[Code of Conduct](https://github.com/sahil-me/free-iptv-aggregator/blob/main/CODE_OF_CONDUCT.md)** and help maintain a respectful, welcoming, and collaborative environment for everyone.

---

# Ways to Contribute

There are many ways you can contribute to **OpenStream OTT**.

* **Feature Development** – Add new features such as channel search, favorites, filtering, category browsing, dark mode improvements, or accessibility enhancements.
* **UI / UX Improvements** – Improve responsiveness, animations, layouts, usability, or overall user experience.
* **Streaming Enhancements** – Improve stream playback, channel organization, loading states, or error handling.
* **Performance Optimization** – Optimize rendering, reduce bundle size, improve loading speed, or enhance application performance.
* **Bug Fixes** – Identify and resolve issues related to streaming, navigation, responsiveness, or application behavior.
* **Code Quality** – Refactor components, improve maintainability, simplify logic, or follow modern React and TypeScript best practices.
* **Documentation** – Improve the README, setup instructions, screenshots, deployment documentation, or code comments.
* **Testing** – Add or improve automated tests to increase application reliability.

> Every contribution, no matter how small, is greatly appreciated. ❤️

---

# Reporting Bugs

If you discover a bug, please open an issue and include as much information as possible.

Helpful information includes:

* Operating System and version
* Browser and version
* Device type (Desktop / Mobile)
* Steps to reproduce the issue
* Expected behavior
* Actual behavior
* Screenshots or screen recordings (if applicable)
* Console errors (if available)

Before creating a new issue, please check whether it has already been reported.

# Requesting a Feature

Have an idea to improve **OpenStream OTT**?

Open an issue and describe:

1. The problem your feature solves.
2. Your proposed solution.
3. How the feature should work.
4. Mockups, screenshots, or examples (if applicable).

Well-described feature requests help us review and implement improvements more efficiently.

# Fixing Outstanding Issues

If you notice an issue with the existing code and have a fix in mind, feel free to **[start contributing](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request)** and open a Pull Request.

## Making Code Contributions

<details>

### 1. Fork the Repository

  - Go to the GitHub repository and click the **Fork** button.

### 2. Clone Your Fork

  ```bash
  git clone https://github.com/<your-username>/free-iptv-aggregator.git
  ```

  ```bash
  cd free-iptv-aggregator/frontend
  ```

### 3. Install Dependencies

  ```bash
  npm install
  ```

### 4. Create a New Branch

  ```bash
  git checkout -b feature/your-feature-name
  ```

### 5. Make Your Changes

  - Write clean, readable, and maintainable code.
  - Follow the existing project structure.
  - Keep React components modular and reusable.
  - Follow TypeScript best practices.
  - Test your changes before committing.

### 6. Commit Your Changes

  ```bash
  git add .
  git commit -m "Describe your changes"
  ```

### 7. Push Your Branch

  ```bash
  git push origin feature/your-feature-name
  ```

### 8. Create a Pull Request

  Submit a Pull Request with a clear description of:
  
  - What you changed
  - Why the change was made
  - Screenshots (if UI changes)
  - Demo video (optional)

### 9. Respond to Feedback

  If reviewers suggest improvements, update your Pull Request accordingly.

</details>

# Development Guidelines

When contributing, please try to follow these principles:

- Keep components focused on a single responsibility.
- Write reusable and maintainable React components.
- Follow TypeScript best practices.
- Maintain consistency with the existing project structure.
- Preserve responsive behavior across devices.
- Optimize performance wherever possible.
- Ensure new functionality does not break existing features.

# Becoming a Maintainer

This project welcomes contributors who are interested in helping maintain and improve the application.

Contributors who consistently provide high-quality improvements, review pull requests, improve documentation, improve test coverage, and actively participate in the project may be invited to become maintainers.

We appreciate every contribution and look forward to collaborating with you! 😊
